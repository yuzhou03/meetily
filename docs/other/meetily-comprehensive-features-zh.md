# Meetily 功能与能力概览

Meetily 核心功能、技术能力、优势、局限、差异化定位及目标用户的综合参考文档。

## 核心功能与技术能力

### 实时本地转录

- 使用 **Whisper** 或 **Parakeet** 语音转文字模型，实时捕获并转录会议内容。
- 所有转录任务**完全在本地设备上运行** — 音频数据绝不会发送至外部服务器。
- 支持多种语言的转录。

### AI 驱动的会议摘要

- 通过可配置的 LLM 后端生成结构化的会议摘要。
- 支持的服务商：
  - **Ollama**（本地部署，推荐用于隐私保护）
  - **BuiltInAI**（通过 llama-helper sidecar 实现的本地 Llama）
  - **Claude**（Anthropic）
  - **OpenAI**（GPT-4o、GPT-4o-mini）
  - **Groq**（高速推理）
  - **OpenRouter**（多模型网关）
  - **自定义 OpenAI 兼容端点**（自建或第三方）

### 专业级音频引擎

- 同时捕获**麦克风与系统音频**。
- 智能音频闪避（ducking）与削波（clipping）预防。
- 专业级多说话人音频混音，确保清晰的录音质量。

### 导入与增强（Beta）

- 导入已有的音频文件以生成转录文本。
- 使用不同的模型或语言对已录制的会议重新转录。
- 所有导入与增强处理均在本地完成。

### GPU 加速

硬件加速已内置，并在构建时自动启用：

| 平台 | 加速方式 |
|------|---------|
| macOS（Apple Silicon） | Metal + CoreML |
| Windows / Linux（NVIDIA） | CUDA |
| Windows / Linux（AMD/Intel） | Vulkan |
| Linux（AMD ROCm） | HIP BLAS |
| 无可用 GPU | 基于 OpenBLAS 优化的 CPU 回退方案 |

### 灵活的数据持久化

- 本地 **SQLite** 数据库，用于存储会议元数据、转录文本和摘要。
- 所有数据 — 模型、录音、转录文本、摘要 — 均存储在本地设备上。
- 支持数据库导入/导出，便于备份与迁移。

### 跨平台支持

- **macOS** — Apple Silicon 与 Intel，发布格式为 `.dmg`。
- **Windows** — x64，发布格式为 `.exe`（NSIS 安装包）和 `.msi`。
- **Linux** — 从源码构建，自动检测 GPU。

### 开源与可扩展

- MIT 许可证，完全开源。
- 基于 Tauri 架构，Rust 与 Web 开发者可独立贡献。
- 支持自定义摘要模板与工作流（Meetily PRO）。

## 关键优势（优点）

1. **完全的数据主权** — 零数据外泄。非常适合受监管行业（国防、医疗、法律、金融）。
2. **无持续性 API 成本** — 使用免费的开源 AI 模型（Whisper、Parakeet、Ollama），无需昂贵的云端 API。
3. **离线优先** — 使用本地模型时，无需互联网连接即可完全运行。
4. **隐私优先设计** — 无遥测、无云同步、无第三方数据访问。
5. **规模化下的高性价比** — 无按席位或按时长计费，可在自有硬件上运行。
6. **硬件加速** — 自动检测 GPU，在支持的硬件上最大化转录速度。
7. **多服务商灵活性** — 可在本地与云端 AI 服务商之间自由切换，工作流无需改变。
8. **专业级音频质量** — 双通道采集（麦克风 + 系统音频），智能混音。
9. **轻量级桌面应用** — Tauri 框架生成的二进制文件体积小、内存占用低，优于基于 Electron 的同类产品。
10. **活跃的开源社区** — 定期贡献、透明的开发流程、社区驱动的功能路线图。

## 局限与改进方向（缺点）

1. **无说话人分离（社区版）** — 无法自动区分不同的说话人。*（计划于六月中旬在 PRO 版本中提供。）*
2. **Linux 需从源码构建** — 没有预编译的 Linux 二进制文件；需要使用 Rust 与 Node.js 工具链手动编译。
3. **本地模型质量** — 开源的 Whisper/Parakeet 模型在某些口音或嘈杂环境下的准确率可能低于商业云端 API。
4. **聚焦单用户** — 社区版面向个人使用设计；团队协作功能仅限于 PRO 版本。
5. **暂未集成日历** — 会议需手动启动；自动日历同步功能计划在 PRO 版本中提供。
6. **暂未支持"与会议对话"功能** — 社区版暂不支持通过自然语言查询会议内容。
7. **建议配备 GPU 以获得最佳性能** — 仅 CPU 模式可以工作，但处理长会议或高质量模型时速度会明显变慢。
8. **导出格式** — 社区版支持 Markdown 导出；高级格式（PDF、DOCX）仅在 PRO 版本中提供。

## 与竞品方案的差异化

| 维度 | Meetily | 云端替代方案 | 其他开源工具 |
|------|---------|-------------|-------------|
| **数据位置** | 100% 本地设备 | 厂商服务器 | 不一而足 |
| **转录引擎** | 本地 Whisper / Parakeet | 专有云端 API | 常需依赖外部 API |
| **离线支持** | 完整的离线能力 | 需联网 | 部分支持 |
| **成本** | 免费（MIT 许可） | 按席位/按时长计费 | 免费，但可能需要付费 API |
| **GPU 加速** | 内置，自动检测 | 不适用（云端） | 需手动配置 |
| **AI 摘要服务商** | 7 家服务商 + 自定义端点 | 单一厂商 | 数量有限 |
| **应用体积** | 轻量（Tauri） | 不适用（基于 Web） | 不一（多为 Electron） |
| **隐私合规** | 零数据外泄 | 取决于厂商 | 取决于实现方式 |

### 核心差异化优势

- **隐私优先架构** — 不同于 Otter.ai、Fireflies.ai 或 Microsoft Copilot，Meetily 绝不会将音频或转录文本上传至外部服务器。
- **自包含的桌面应用** — 单个可安装的二进制文件，无外部依赖或浏览器要求。
- **模型灵活性** — 用户可自由选择转录模型与 LLM 服务商，避免厂商锁定。
- **企业级隐私就绪** — 专为禁用云端工具的 GDPR、HIPAA 及国防行业的合规要求而设计。

## 目标使用场景与受众

### 主要受众

- **注重隐私的专业人士** — 处理敏感讨论的律师、医生、咨询师及企业高管。
- **企业团队** — 具有严格数据治理、合规或气隙隔离需求的组织。
- **开发者与工程师** — 偏好开源工具与本地优先工作流的技术用户。
- **研究人员与学者** — 需要可靠转录而又无需签署数据共享协议的个人。

### 理想使用场景

| 场景 | 选择 Meetily 的原因 |
|------|---------------------|
| 法律咨询 | 律师与客户之间的特权要求零数据外泄 |
| 医疗会议 | HIPAA 合规要求仅限本地处理 |
| 国防与政府 | 无互联网接入的气隙环境 |
| 董事会会议 | 敏感的企业战略讨论 |
| 客户访谈 | 机密信息不得离开设备 |
| 学术研究 | IRB（机构审查委员会）对数据处理的要求 |
| 个人生产力 | 免费、随时可用的会议笔记 |

### 何时考虑 Meetily PRO

- 需要**说话人分离**以区分多个参与者。
- 需要**高级导出格式**（PDF、DOCX）以满足正式文档需求。
- 希望使用**自定义摘要模板**以适配特定工作流。
- 需要**自动会议检测**以实现免手动录音。
- 处于**团队或自建部署**场景（2–100 名用户）。
